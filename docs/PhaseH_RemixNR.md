# Phase H — Remix: закрыть фазу G, замерить, перейти на main с нейрорендерингом

> **Статус (2026-10-08):** план утверждён пользователем 2026-10-08: решения программы P1–P12
> (`project-empty/docs/NR_PT_Program.md`) приняты — явно P5 и P6, остальные по рекомендации; местные
> вопросы Q1–Q10 ниже открыты (у каждого — рекомендация). Отчёт исследования —
> `yae-dlss5/reports/Нейрорендеринг и трассировка пути для YAE.md`. Железо (пользователь, 2026-10-08):
> Linux и Windows с игрой — один ПК с RTX 5090; прогоны Remix фазы G шли на нём под Windows; есть
> RTX 3060 Laptop 6 ГБ. Разведка статическая, 2026-10-08: код и
> история этого репозитория, клон `dxvk-remix` main, публичный CI и CDN пакетов NVIDIA. Игра не
> запускалась — игровой ПК с Windows и RTX 50 в этой сессии недоступен, — поэтому каждая подфаза,
> которая меняет картинку или скорость, начинается с замера. Порядок фаз и их гейты —
> [`Roadmap.md`](Roadmap.md).

> **Цель.** Закрыть фазу G (RTX Remix 1.5.2) так, как здесь закрываются фазы: раздел в `STATUS.md`,
> профиль без ручных шагов, журнал по уровням и числа. Затем перевести уровень P («трассировка пути
> + NR») на закреплённый коммит `dxvk-remix` main с собственным проходом NR Remix
> («DLSS 3D-Guided Neural Generation») на RTX 50 — с измеренной ценой, умолчаниями YAE, масками,
> профилями `rtx.conf` по классам GPU и проверенной стабильностью.

> **Принцип.** Трассировка пути с авторским светом и материалами — основной путь реставрации; NR —
> опция поверх неё (P3): по умолчанию выключен, мгновенный A/B, интенсивность, маски существ и лиц,
> проверка гистограмм тёмных сцен. Сначала замер, потом правка: изменение картинки или скорости сдаётся
> числами «до/после» и контролем той же конфигурации (два одинаковых прогона дают порог шума). Ресурсы
> игры (`.ds2*`) не меняются. Этот репозиторий не заменяет `yae-dlss5` (P1): уровень R — самый широкий по
> GPU, уровень P — только для RT-карт.

## Как устроено

### Цепочка и что в ней трогает фаза H

```
YOU_ARE_EMPTY.EXE (x86, LAA) ─ ds2render.dll ─ opengl32.dll = QindieGL ─────────────── QindieGL.log
                                                │ yae_camera_split = 1 → D3DTS_VIEW + WORLD       (PERF, CAMERA_SPLIT,
                                                │ remix_server_all_cpus = 1                         REMIX, census)
                                                ▼
                                        d3d9.dll = клиент моста (x86) ── IPC: каждый вызов D3D9
                                                ▼
                    .trex\NvRemixBridge.exe (x64) ─ .trex\d3d9.dll = dxvk-remix (закреплённый main)
                         rtx.conf ← профиль H.8     │  .trex\nvngx_dlssnr.dll (своя у пользователя, P4)
                         rtx-remix\mods\YAE-NR\     │
                           mod.usda ← маски H.7     ▼
   трассировка → денойз → апскейл → [быстрый тонмаппинг → NR → обратный] → bloom → тонмаппинг → … → DLFG
                                                                                       → UI DS2 поверх
   rtx-remix\logs\*.log · metrics.txt · Screenshots\ (кадр до UI)
```

QindieGL в фазе H почти не меняется: разделение камеры, сродство CPU и мировые позиции ламп уже
есть. Новое в коде — только по решениям: клавиша A/B (Q4) с заголовками Remix API 0.6.5 и, если
понадобится, диагностический дамп хэшей текстур. Остальное — конфигурация, моды и измерение.

### Стенд замеров (H.5)

- **Сцены.** Пять ретейл-слотов движка (R33): неподвижная поза камеры, повторяемая между прогонами,
  между 1.5.2 и main и между уровнями R, P и N — те же слоты дают эталонные сцены движка. Сценарий
  копирует их в `savegames` игры под своими именами и не трогает сейвы игрока.
- **Запуск.** `YOU_ARE_EMPTY.EXE -exec_cmd "smap Save78"` (и т. д.) с окружением, которое унаследует
  сервер моста (проверить в H.5): `DXVK_METRICS_PATH`, `DXVK_TERMINATE_APP_FRAME=<N>`,
  `DXVK_DUMP_SCREENSHOT_FRAME=<N−1>`, `DXVK_SCREENSHOT_PATH`; в профиле стенда
  `rtx.automation.metricsWarmupFrames` ≈ 300 — прогрев NRC и денойзеров (число уточняется замером
  сходимости). Если завершение сервера по кадру грубо роняет клиент моста — сценарий закрывает игру сам.
- **Источники чисел — три, они меряют разное.** `metrics.txt` Remix — среднее время кадра на стороне
  рантайма, простой GPU, видеопамять. `QindieGL.log` — время кадра игры (avg/p95/p99) и доля `Present`,
  то есть ожидание моста и сервера; тот же слот без Remix (`-Remix Off`) — для сравнения времени внутри
  вызовов D3D9: разница — цена клиента моста на CPU. PresentMon
  на `NvRemixBridge.exe` — распределение времени между презентами (swapchain Vulkan создаёт сервер;
  проверить, что PresentMon его видит). Окно «Reflex Latency Stats» — ручная сверка (только NVIDIA).
  Цена прохода NR отдельно от кадра — GPU-зона «DlssNeuralRendering» в сборке с Tracy или в захвате
  Nsight; по умолчанию цена NR = разница среднего кадра «NR вкл. − выкл.».
- **Разрешения.** 1920×1080 (проверено с DS2); 2560×1440 и 3840×2160 — пробуем в полноэкранном и
  оконном режиме (3440×1440 DS2 не инициализировал, R8).
- **Порог шума.** Каждый прогон дважды; разница двух одинаковых прогонов — порог (Q10: ≤ 3 %).
  Изменение меньше порога не засчитывается — правило движка «контроль той же конфигурации».
- **Уровни.** 24 уровня кампании меряются грубее: `PERF` QindieGL за 5 минут ходьбы. Дорожек камеры
  оригинал не воспроизводит (R33), поэтому p99 с маршрутов — ориентир, а не гейт.
- **Отчёт.** JSON на прогон: GPU, вендор, драйвер, VRAM, CPU, Windows, разрешение, профиль, коммит
  Remix, хэш сборки QindieGL; по слоту — средний кадр Remix, простой GPU, память, avg/p95/p99 и доля
  `Present` QindieGL. Сводка — в `STATUS.md`; формат совпадает с отчётами лаборатории (P11).
- **Что потом запускают тестеры.** `Measure-YAERemix.ps1 -Profile <уровень>` на своей копии игры с
  LAA, нашей сборкой QindieGL и закреплённым пакетом Remix: проверка установки (LAA, цепочка, мост,
  профиль), пять слотов, архив с JSON и логами. «Не стартует» (ожидаемо для Arc: в июне 2026 HL2 RTX
  на Arc не запустился у PCGH, см. риски в `Roadmap.md`) — тоже результат, а не ошибка сценария.

### Сборка закреплённого main (H.6a)

1. Коммит — по Q2 (сейчас `e4e7303d6d`).
2. Требования README `dxvk-remix`: Windows 10/11, VS 2019/2022, Windows SDK 10.0.19041.0, Meson
   1.8.2, Vulkan SDK ≥ 1.4.313.2, Python ≥ 3.9, DirectX Runtime.
3. `git clone --recursive`, `git checkout <коммит>`, `git submodule update --init --recursive`;
   `build_dxvk_all_ninja.ps1` (или `meson setup`/`meson compile` только для `_CompRelease_x64`).
   Packman тянет `packman-external.xml`; в логе — `rtx-remix-ngx_sdk_dlnr@1` с SHA-256 из R21.
4. Мост — `bridge\build_bridge_all.bat` (клиент x86 и сервер x64).
5. Раскладка — как у артефакта `rtx-remix-for-x86-games-*`: `d3d9.dll` (клиент x86) у игры, в `.trex\`
   — `NvRemixBridge.exe`, `d3d9.dll` (рантайм x64), зависимости, `usd\`.
6. Сверка с артефактом CI NVIDIA того же коммита: список файлов и версии зависимостей (NGX, NRC, NRD,
   XeSS). Побайтного равенства не ждём.
7. В `.trex\` — своя `nvngx_dlssnr.dll` пользователя (P4).
8. Записать коммит, SHA-256 всех файлов пакета, версии VS/SDK/Vulkan SDK, лог packman.

Запасные пути, если пакет NR исчезнет или закроется: локальный кэш packman на машине сборки; артефакт
CI NVIDIA (90 дней); форк lunks (R31); свой вызов NGX с известным сообществу набором параметров
(структуры видны по месту вызова, `rtx_ngx_wrapper.cpp:1060-1115`, но определения пришлось бы
восстанавливать без пакета); `yae-neural` в фазе J.

### NR: экспозиция, умолчания, маски, A/B (H.7)

- **Экспозиция прокси.** По R18 NR в профиле G работает на кадре темнее экранного. Два варианта — как
  есть и `rtx.tonemap.exposureBias = 2,41` (влияет только на прокси NR и на глобальный тонмаппер,
  которым YAE не пользуется), — сравниваются по проверке тёмных сцен и по листу A/B (Q8).
- **Лист A/B.** Пять slot-сцен × {NR выкл.; модели A, B, C при интенсивности 0,5 и 1,0} = 35 кадров до
  UI. По нему пользователь выбирает модель и интенсивность или решает, что NR в уровне P не нужен (Q6).
- **Проверка тёмных сцен.** На кадрах до UI (`DXVK_DUMP_SCREENSHOT_FRAME` или «Take Screenshot»):
  уровень чёрного (1-й перцентиль яркости), доля почти чёрных пикселей, средняя яркость, 99-й
  перцентиль (блики). NR выкл. против вкл. при выбранных умолчаниях, контроль — два прогона «выкл.».
  Пороги — Q10.
- **Маски существ и лиц.** Категории текстур Remix маской NR не управляют (R26), но тот же инструмент
  разметки (Alt+X → Game Setup → Categorize Textures, клик по объекту) даёт хэши. Хэши существ и лиц
  собираются вместе с декалями (H.4); генератор пишет `rtx-remix/mods/YAE-NR/mod.usda`: на каждый хэш
  `over "mat_<HASH>"` с шейдером `AperturePBR_Opacity` и только полями маски —
  `inputs:enable_dlss_control_mask = 0` (исключить) или пониженные `…_tone_strength` /
  `…_structural_strength` (ослабить). Альбедо и прочее Remix берёт из игры (R24). Через Remix API так
  нельзя: его материалы видны только мешам API (R24), и клиент 0.5.1 мост не примет (R25).
- **Туман и полупрозрачное.** У полупрозрачных материалов полей маски нет (R23); их ослабляет
  `enableVolumetricControlMask` (туман, объёмы, альфа-смешанное пропускание). Работает, только если
  туман DS2 доходит до Remix (`rtx.enableFog`, туман D3D9) — в фазе G это не записано, H.3 записывает.
- **A/B.** Мгновенный переключатель — клавиша QindieGL (Q4: `SetConfigVariable("rtx.dlssNeuralRendering.enable", …)`,
  интенсивность — так же), иначе меню разработчика Remix. В настройках игрока NR всегда стартует
  выключенным (P3).

### Профили по классам GPU (H.8)

Состав — таблица «GPU stack by tier» в [`Roadmap.md`](Roadmap.md): Portable, RTX 20/30, RTX 40, RTX 50 и
RTX 50 + NR. Каждый файл — это общий блок YAE (ключи фазы G, теги текстур, FG выкл. до H.9),
**`rtx.graphicsPreset = 4` (Custom)** — иначе значения пресета перекроют профиль (R27), — и ключи своего
класса GPU. `Set-YAEDllChain.ps1 -Profile <имя>` собирает их в `<игра>\rtx.conf` (исходники живут в репозитории:
Remix переписывает `rtx.conf` без комментариев при сохранении из меню), узнаёт свои файлы по строке
заголовка и отказывается трогать чужие, предупреждает, если `user.conf` перекрывает ключ профиля, и
печатает подсказку по GPU (вендор, имя) без автоприменения. `DXVK_RTX_CONFIG_FILE` (R27) не используем:
переменная должна дойти до окружения сервера моста и прячет профиль от игрока. Числа есть только для
RTX 50 (наш RTX 5090); остальные профили помечены «гипотеза — ждёт отчёта лаборатории (P11)».

### Стабильность (H.9)

| Что | Почему | Как проверяем |
|---|---|---|
| Генерация кадров (DLFG) | падение в `vkQueueSubmit` на 1.5.2 (R6); на main — `7e50b74` и `1f10dd6`, которых в 1.5.2 нет (R15) | 2× на `med1` и на тяжёлом уровне по 30 минут, затем MFG; при падении — дамп `.trex\NvRemixBridge.exe_*.dmp`, лог, issue в `rtx-remix` |

### Контракт C5 для glhook (H.10)

`docs/DS2View.md` (по-английски, P12) описывает то, что `yae-dlss5` D2 переносит в свой перехватчик:
правило камеры (сброс modelview и одно `glMultMatrixf` на глубине стека 0; первое преобразование после
сброса — вид), классы проекций (`P<near>-<far>`, `O`, `I`) и виды матрицы (none/rot/rigid/mirror/affine/proj),
камеру неба (только поворот, рисуется первой), проекцию оружия, силуэтный проход 512×512 при
включённых тенях, признаки границы «мир → HUD» (перспектива → орто, выключение теста и записи
глубины), лампы в мировых координатах под камерой. Каждое правило — со ссылкой на код
(`code/d3d_matrix.cpp:103-190`, `code/d3d_view_diagnostics.cpp:13-17,559-582`, `code/d3d_light.cpp:32-49`)
и на тест, который его держит (`tests/camera_split_tests.cpp`, `tests/view_tests.cpp`).

  (`yae-dlss5` D1, D2): сессии замеров планируются, код и документы пишутся параллельно.

## Исключено

- **Внешняя цепочка `yae-dlss5` поверх Remix** (ReShade, Feeder, OptiScaler). Remix рисует в отдельном
  x64-процессе сервера моста; по DLSS5-Autopilot ReShade роняет Remix-игру до первого кадра; входы были
  бы хуже собственного прохода Remix (кадр с HUD, оптический поток). Уровень R остаётся отдельным уровнем.
- **Маски NR через Remix API 0.6.5.** Материалы API видны только мешам API (R24); пришлось бы передавать
  геометрию через API — путь «перехватить `ds2render` и кормить Remix API», который отчёт держит в резерве.
- **Категория текстур для масок NR** — такой категории нет (R26).
- **Остаться на 1.5.2.** Нет NR, DLSS 4.5, исправлений FG (R15); следующий тег не объявлен.
- **Пресет Auto для YAE.** Перекрывает `rtx.conf`, на не-NVIDIA сразу Low (R27).
- **OptiScaler внутри Remix ради FSR.** Генерация кадров с ним падает (OptiScaler wiki, 2026-09-25);
  FSR 3.1 — в фазе J через форк.
- **Путь шейдеров DS2 под Remix (фаза F).** Вершинные ARB-программы перевели бы вызовы на vertex capture
  с хэшами, меняющимися от анимации; трассировка всё равно заменяет шейдинг.
- **Тени DS2 под Remix** — силуэтный ортопроход Remix принимает за UI, кадр мерцает (R8).
- **Статические VBO сейчас** — только если H.5 покажет копирование вершин узким местом под Remix
  (условная работа после фазы, `STATUS.md:812-817`).
- **Флаг сборки NR.** Его нет: NR компилируется всегда, включается опциями времени выполнения (R20).
